## 2. Проверка логики — 6 найденных дефектов

### Д1. Дубли комплексов внутри «Базы» — 74 строки
Фильтр вьюхи был написан «от противного»: `status NOT LIKE 'вычтен%'`. Статус
`дубль_в_базе`, введённый миграцией 019, под него не попадал — и 74 БЦ, уже
помеченных дублями других строк Базы, продолжали показываться.

### Д2. ВУЗ / НИИ / колледжи (1 118 строк) — вне всякого контроля
Вторая половина «Базы» берётся из `kosmos.places` и не имела **ни фильтра
статуса, ни вердикта**. Последствия:
- вычитание точек МИЛТИ их **никогда не касалось** — скрипт ходил только по зданиям;
- отклонить их (Хуй) было физически нечем.

### Д3. 20 адресов МИЛТИ остались в «Базе»
Прямое следствие Д2. Проверено точным расстоянием ≤30 м:
13 НИИ, 6 ВУЗ, 1 колледж. Примеры: «Гипромез», просп. Мира 101с1 — закрытая точка
в 5 м; «Центр инноваций Объединённые кондитеры», Бауманская 16с1 — 4 м;
«НИИ Ипромашпром», Суворовская пл. 1/52к2 — работающая точка в 22 м.
**По зданиям (БЦ, офисные) остатков ноль — там вычитание отработало верно.**

### Д4. Дубли по названию+адресу — 16 групп
Один комплекс двумя строками: реестр + внешний каталог.

### Д5. ОК/Хуй был только в одном листе
Колонка «Решение» стояла лишь в «На проверку». В «Базе», ТЦ, «Конкурентах»,
«БЦ средних» решения не было вообще. У «Конкурентов» не было даже колонки-ключа,
то есть решение некуда было привязать.

### Д6. Вердикт нельзя было выставить местам
`kosmos.verdicts.object_id` — внешний ключ на здания. У ВУЗ/НИИ/конкурентов строки
в зданиях нет, поэтому ОК/Хуй для них не мог существовать в принципе.

### Бонус: сверка адресов молча не работала
Нормализация адреса резала «улица / дом / строение» регэкспом с `\b`. В JavaScript
`\b` определён по латинице — между пробелом и кириллической буквой границы слова
нет, поэтому **ни одно правило не срабатывало**, и в ключ уезжали «дом», «переулок»,
«москва». Сверка по адресу держалась только на совпадении координат. Найдено тестом.
