# NocoDB — рабочий стол Димы

Разворачивается **рядом** с n8n на makersai.ru, ничего существующего не трогает. Отдельный контейнер, отдельный порт, отдельная база под метаданные.

## Что это и почему так

Postgres — источник правды. NocoDB — витрина поверх него, подключённая как **внешний источник данных**. Копии нет: Дима смотрит и правит настоящую базу, синхронизировать нечего.

Это принципиально отличается от «завести таблицы внутри NocoDB»: в своей схеме у нас остаются CHECK-констрейнты (площадь без источника не запишется), вставка 42 650 строк одной транзакцией, вид `v_leads` и SQL для аналитика. Диме при этом одинаково — он видит ту же сетку.

## Развёртывание

```yaml
# docker-compose.yml — фрагмент, добавить к существующему стеку
services:
  nocodb:
    image: nocodb/nocodb:latest
    container_name: kosmos-nocodb
    restart: unless-stopped
    ports:
      - "127.0.0.1:8090:8080"   # наружу только через реверс-прокси
    environment:
      # Метаданные самого NocoDB. ОТДЕЛЬНАЯ база, не kosmos:
      # схему реестра NocoDB трогать не должен.
      NC_DB: "pg://postgres:5432?u=nocodb&p=${NOCODB_META_PASSWORD}&d=nocodb_meta"
      NC_PUBLIC_URL: "https://kosmos.makersai.ru"
      NC_DISABLE_TELE: "true"
    volumes:
      - kosmos_nocodb:/usr/app/data

volumes:
  kosmos_nocodb:
```

Порт наружу не открываем — только через реверс-прокси с HTTPS. База лидов отдела развития — коммерческая тайна.

## Подключение реестра как внешнего источника

В интерфейсе: **Base → Data Sources → New Data Source → PostgreSQL**.

| Поле | Значение |
|---|---|
| Host | `postgres` (имя сервиса в сети docker) |
| Port | `5432` |
| Database | `kosmos` |
| Schema | `kosmos` |
| User | `kosmos_reader` (см. ниже) |

## Права — здесь легко всё сломать

**Критично: вид на `objects` обязан быть только для чтения.**

Если Дима сможет править `objects` из интерфейса, следующий прогон обогащения **молча затрёт его правку** — и он об этом не узнает. Это ломает главный инвариант: машина пишет в `objects`, человек — в `verdicts`.

Защита в два слоя, потому что одного мало.

**Слой 1 — права в самом Postgres.** Отдельная роль, у которой физически нет прав на запись в `objects`. Даже если кто-то случайно включит галочку в NocoDB, база не даст:

```sql
CREATE ROLE kosmos_reader LOGIN PASSWORD 'задайте_свой';

GRANT USAGE ON SCHEMA kosmos TO kosmos_reader;

-- Чтение реестра
GRANT SELECT ON kosmos.objects, kosmos.observations, kosmos.v_leads
  TO kosmos_reader;

-- Вердикты — единственное, куда человек пишет
GRANT SELECT, INSERT, UPDATE ON kosmos.verdicts TO kosmos_reader;
GRANT USAGE, SELECT ON SEQUENCE kosmos.verdicts_id_seq TO kosmos_reader;

-- Списки точек Дима обновляет раз в месяц
GRANT SELECT, INSERT, UPDATE, DELETE
  ON kosmos.our_points, kosmos.closed_points TO kosmos_reader;
GRANT USAGE, SELECT ON SEQUENCE kosmos.our_points_id_seq TO kosmos_reader;
GRANT USAGE, SELECT ON SEQUENCE kosmos.closed_points_id_seq TO kosmos_reader;
```

**Слой 2 — настройки NocoDB.** В источнике данных: `Allow Schema Edit` = **off**, `Allow Data Edit` = **off**.

Порядок важен: в NocoDB редактирование данных отключается, только если отключено и редактирование схемы.

Отключение правки **не мешает** фильтровать, сортировать и группировать — а именно это Диме и нужно.

## Виды вместо листов

Дима просил девять листов Google-таблицы. Здесь это девять **видов** над одной таблицей — то же для глаз, без девяти копий данных. Лист = сохранённый фильтр.

| Вид | Фильтр |
|---|---|
| `БЦ` | `object_type = 'бц'` И `area_sqm >= 10000` |
| `Офисные здания` | `object_type = 'офисное_здание'` И `area_sqm >= 10000` |
| `Офисы компаний` | `object_type = 'офис_компании'` |
| `НИИ` | `object_type = 'нии'` |
| `ВУЗы` | `object_type = 'вуз'` |
| `Конкуренты` | `object_type = 'конкурент'` |
| `НА ПРОВЕРКУ` | `area_confidence = 'оценка'` И `area_sqm` между 8000 и 10000 |
| `В СТРОЙКЕ` | `object_type = 'в_стройке'` |
| `Изменения за неделю` | `first_seen_at` за последние 7 дней |
| `Вычтено` | `status` начинается с `вычтен` |

`Вычтено` — обычный вид, не скрытый. Дима должен иметь возможность проверить, не вычли ли мы лишнего — а однажды вычтем.

## Подсветка новых

Условное форматирование по `first_seen_at`: подсвечено **28 дней** от первой находки, а не одну неделю. Если Дима был в отпуске две недели, он не должен потерять всё новое.

Дата запуска (`commissioning_date`) — отдельная колонка, не выцветает никогда.

**Важно про первый запуск:** пока `baseline_run = true`, ничего не подсвечивается. Иначе Дима в первое воскресенье получит 3 400 «новых» БЦ и закроет вкладку.

## Русские названия колонок

В базе колонки на латинице (`area_sqm`), Диме нужны русские («Площадь, м²»). Переименовывать в SQL не надо — NocoDB хранит отображаемые имена отдельно от схемы. Меняется в интерфейсе, база не трогается.

Вид `kosmos.v_leads` уже отдаёт колонки по-русски — его можно подключить как есть.

## Доступ

По приглашениям, роль **Viewer** для тех, кто только смотрит. Дима — **Editor** (ему нужны вердикты и списки точек).

Публичные ссылки (`Shared View`) **не включать** без решения Димы: это доступ без пароля для любого, у кого есть URL.
